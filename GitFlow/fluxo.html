Fluxo GitFlow

Release branch strategy dirigida por tags. Você cria branches e tags com git e gh; o GitHub Actions só reage ao push. Não há bot, GitHub App nem secret de release.

Fluxo regular

Clique em um número no diagrama ou no título de um passo para destacá-lo.

main branches de trabalho release/v* production fast-forward

Quem faz o quê

Você (mantenedor)

  • Cria release/v* a partir de main ou production
  • Cria as tags vX.Y.Z-rc.N e vX.Y.Z (anotadas)
  • Faz o fast-forward de production
  • Abre e mergeia o back-merge

GitHub Actions

  • pr-checks, ci, security nos PRs
  • ci em push de main e release/v*
  • release.yml no push de tag: valida, testa, empacota, atesta, publica e faz deploy
  • Nunca cria branches nem tags

Colaboradores

  • Trabalham em feature/*, bugfix/*, hotfix/*, chore/*
  • Entregam só por PR
  • Não criam release/*, tags v* nem tocam em production
  • O agente pode executar os passos do mantenedor quando você pedir, um por vez

Passos e verificação

1

Desenvolvimento

Você executa
git switch main && git pull
git switch -c feature/issue-42-export-csv
git commit -m "feat(report): adiciona exportação em CSV"
git push -u origin feature/issue-42-export-csv
gh pr create --base main --title "feat(report): adiciona exportação em CSV"
Actions
  • pr-checks (nome da branch × destino, título), ci, security
Conferir
2

Corte da release

Você executa
git switch main && git pull && git fetch origin --tags
git describe --tags --abbrev=0 --match 'v[0-9]*' --exclude '*-rc.*'
git cliff --bumped-version
git push origin "origin/main:refs/heads/release/v1.4.0"
Actions
  • ci roda no push de release/v1.4.0
Conferir
3

Release candidate

Você executa
git fetch origin --tags
git tag -a v1.4.0-rc.1 origin/release/v1.4.0 -m "Release candidate v1.4.0-rc.1"
git push origin v1.4.0-rc.1
gh run watch
Actions — release.yml
  • Recusa tag leve e RC fora de release/v1.4.0
  • CI, pacote, atestação, pre-release, deploy em staging
Conferir
4

Correção na release

Você executa
git switch -c bugfix/corrige-export origin/release/v1.4.0
git commit -m "fix(report): corrige separador do CSV"
git push -u origin bugfix/corrige-export
gh pr create --base release/v1.4.0 --title "fix(report): corrige separador do CSV"

Após o merge (squash) e o CI verde, repita o passo 3 com v1.4.0-rc.2.

Conferir
5

Promoção para produção

Você executa
VERSION=v1.4.0
git fetch origin --tags
rc=$(git tag -l "$VERSION-rc.*" --sort=-v:refname | head -n1)
commit=$(git rev-list -n1 "$rc")
git tag -a "$VERSION" "$commit" -m "Release $VERSION (promovida de $rc)"
git push --atomic origin "$commit:refs/heads/production" "refs/tags/$VERSION"
gh run watch
Actions — release.yml
  • Tag anotada, igual ao HEAD de production e ao commit do último RC
  • Pre-release do RC existe
  • CI, pacote, atestação, GitHub Release (latest), deploy em production
Conferir
6

Back-merge

Você executa
gh pr create --base main --head release/v1.4.0 \
  --title "chore(release): back-merge v1.4.0" \
  --body "Merge commit, nunca squash."
gh pr merge release/v1.4.0 --merge --auto
Conferir

Fluxo de hotfix

Mesmo pipeline; a release é cortada de production com bump de patch.

1 · Corte a partir de production
git fetch origin --tags
last=$(git describe --tags --abbrev=0 --match 'v[0-9]*' --exclude '*-rc.*' origin/production)
IFS=. read -r major minor patch <<< "${last#v}"
VERSION="v$major.$minor.$((patch + 1))"
git push origin "origin/production:refs/heads/release/$VERSION"
2 · PR do hotfix para a release
git switch -c hotfix/cve-2026-1234 "origin/release/$VERSION"
git commit -m "fix(auth): corrige validação de token expirado"
git push -u origin hotfix/cve-2026-1234
gh pr create --base "release/$VERSION" --title "fix(auth): corrige validação de token expirado"
3 · RC e promoção

Passos 3 e 5 do fluxo regular com o mesmo VERSION.

4 · Back-merge

Passo 6 do fluxo regular.

Se houver uma release regular aberta, leve o hotfix para ela também (cherry-pick em bugfix/* com PR para a release). Sem isso, o push da promoção é recusado porque production não é ancestral da release — é o que impede a regressão do hotfix.
